**Design**

```python
# app/i18n/text.py
def fold(text: str) -> str:
    """Matching key: NFKD → casefold → NFKD → drop non-spacing marks (Mn) → collapse whitespace.
    'Cărturești  Verona' → 'carturesti verona'; ș/ş and ț/ţ (comma-below AND cedilla) → s/t;
    'ℌ' → 'h' (hence the 2nd NFKD after casefold); punctuation and digits are kept (C2 strips them)."""

# app/i18n/format.py
def format_money(amount: Decimal | int, lang: str) -> str
def format_pct(value: Decimal | float | int, lang: str, *, decimals: int = 0) -> str
def format_date(day: date, lang: str, *, with_year: bool = True, with_weekday: bool = False) -> str
```

| | `ro` | `en` |
|---|---|---|
| thousands / decimal separator | `.` / `,` | `,` / `.` |
| money | `10.000 lei` · `30,40 lei` · `-30,40 lei` · `100 lei` | `10,000 lei` · `30.40 lei` · `-30.40 lei` · `100 lei` |
| percent | `77%` · `12,5%` (decimals=1) | `77%` · `12.5%` |
| date | `15 iunie 2026` · `luni, 15 iunie 2026` · `15 iunie` | `15 June 2026` · `Monday, 15 June 2026` · `15 June` |

- **Rounding:** half-up to cents (`Decimal.quantize(Decimal("0.01"), ROUND_HALF_UP)`, the same rule as F2's `to_money`; C1.4 adds a property test that they agree). **Whole amounts drop the decimals** (`10.000 lei`, `100 lei`: the spec examples and the arch texts "1.890 lei/lună", "4.500"), otherwise always 2 decimals (`30,40`). Never `-0`. Grouping via Python's own `format(x, ",.2f")` then a separator swap for RO; **no `locale` / Babel** (process-global and machine-dependent).
- **Strict inputs:** `float`, `bool`, `str` amounts → `TypeError` ("use to_money()"), the money rule enforced at runtime. NaN / ±Infinity / beyond `Decimal` precision → `ValueError`. `format_pct` takes floats too (probabilities are not money) via `Decimal(str(v))`, so `0.285` → `29%` (not float's 28.499…). `decimals` ∈ {0, 1, 2}.
- **Language:** only lowercase `ro` / `en` (`users.language`); anything else → `ValueError`. F2's `Language` members work as-is (StrEnum is a `str`). Until F2 lands the check is a private tuple; C1.4 switches it to `Language(lang)`.
- **Dates:** `datetime` → `TypeError` (a `datetime` *is* a `date`; formatting a UTC timestamp's date can show the wrong Bucharest day, e.g. `2026-06-14T21:30Z` is 15 June there; callers convert via `app.clock` first). Month and weekday names lower-case in RO (`ianuarie … decembrie`, `luni, marți, miercuri, joi, vineri, sâmbătă, duminică`).
- `lei` in every case: the grammatical spoken form ("1 leu", "500 de lei") belongs to A11's `make_speak_text`.

**Contract impact.** 🆕 public functions `app.i18n.format.format_money/format_pct/format_date` and `app.i18n.text.fold`. Not in arch §15; I propose a line there (§5 below). Readers: A5, A4, B13, A11, C2, C4, C5.

**Shape**

```json
{
  "merchants": [
    { "id": "mega_image", "canonical_name": "Mega Image", "aliases": ["mega image", "megaimage"],
      "category": "groceries", "mcc": "5411", "typical_basket": 85.00, "multi_category": false }
  ]
}
```

Schema: `additionalProperties: false` everywhere; `id` `^[a-z0-9]+(_[a-z0-9]+)*$` ≤ 40; `canonical_name` 1–80; `aliases` ≥ 1, `uniqueItems`, each 3–60; `category` `enum` = the 26 values of arch 4.5 (pinned to F2's `Category` by a test); `mcc` `^[0-9]{4}$` **string** (MCCs are codes and may have leading zeros; see dependencies); `typical_basket` number `> 0` (2 dp checked in Python, because `multipleOf: 0.01` is float-fragile for anyone loading without `Decimal`); `multi_category` boolean.

- `id`: a stable slug, the key the seed upserts on and, if Q1 is approved, the `merchants` PK and the `merchant_id` everywhere.
- `typical_basket`: a fictional typical single purchase *for one adult* at that merchant. It is reference data (E12 defaults, question hints). Personal medians come from each persona's history, and the category baselines from E6.

**Alias strategy** (C2 depends on it):
1. Aliases are the spellings that appear in bank descriptors, in lower case and with correct diacritics. C2 strips store numbers, cities and payment prefixes (`POS`, `PAYU*`, `*ORDER`, `SC`, `SRL`), so aliases never contain them.
2. `fold(canonical_name)` is always one of the folded aliases, so C2 is idempotent on canonical names.
3. Within a merchant, aliases are unique after `fold`. No redundant diacritics variant: `cărturești` already covers `carturesti`.
4. **Across merchants, aliases are unique even under the strict key** `re.sub("[^0-9a-z]", "", fold(a))`, so whatever punctuation and space handling C2 chooses, an alias maps to exactly one merchant.
5. Every alias has at least 3 characters after folding (no `dm`, no `h&m`).
6. **Nested aliases** (one merchant's strict key inside another's: `bolt` ⊂ `bolt food`, `digi` ⊂ `digi sport`, `omv` ⊂ `omv petrom`) are pinned as a golden set. C2's longest-match tests must cover each one, and any new nesting becomes a deliberate, reviewed change.
7. The short generic aliases (`mol`, `omv`, `eon`, `digi`, `bolt`, `orange`, `profi`, `zara`) need whole-token matching in C2. This is noted for C2, not enforced here.
