### F1.3 · Clock

**Files.** `app/clock.py` (new), `tests/unit/test_clock.py` (new), `tests/unit/test_architecture.py` (new). If the boss allows: `tests/conftest.py` autouse restore of the installed clock (§6 Q3). The hypothesis profile already exists (H-4): not touched.

**Design.**
```python
APP_TZ: Final = ZoneInfo("Europe/Bucharest")    # resolved at import: a missing tz database fails at startup

@runtime_checkable
class Clock(Protocol):
    def now(self) -> datetime: ...   # aware, tzinfo APP_TZ
    def today(self) -> date: ...     # contract: == now().date() (the Bucharest calendar date)

class RealClock:   now() = datetime.now(APP_TZ); today() = self.now().date()
class FixedClock:  __init__(self, at: datetime)  # naive → ValueError("FixedClock needs a timezone-aware datetime")
                   now() = at.astimezone(APP_TZ) (same instant); today() = now().date()

def get_clock() -> Clock
def set_clock(clock: Clock) -> Clock             # returns the previous one; non-Clock → TypeError
def now() -> datetime                            # get_clock().now()
def today() -> date                              # get_clock().today()
```
- One process-wide clock (1 worker, H-2); bomboe's B10 installs `SimClock` with `set_clock`. The `Clock` docstring states the contract SimClock must keep (`today() == now().date()`, aware, APP_TZ) and the test file has a contract test parametrized over the clocks, so B10 adds SimClock to that list.
- `now()` is Bucharest-aware; JSON timestamps are UTC (arch 9.1): converting is the API layer's job.
- Wall-clock bans cover `now`/`utcnow`/`today`/`time.time`; `time.monotonic()`/`perf_counter()` stay allowed (durations, not dates).

**Contract impact.** 🆕 `app.clock`: `APP_TZ`, `Clock`, `RealClock`, `FixedClock`, `get_clock`, `set_clock`, `now`, `today` (arch §15.1 lists `clock.today(), clock.now()`; these signatures make it precise). B10's SimClock implements `Clock`.

### F1.4 · Error envelope

**Files.** `app/errors.py` (new), `app/main.py` (install + OpenAPI responses), `tests/api/test_errors.py` (new; test-only routes added to a `create_app(settings)` app).

**Design.**
```python
_CODE = re.compile(r"^[a-z][a-z0-9]*(?:_[a-z0-9]+)*$")      # snake_case, ≤ 64 chars

class DomainError(Exception):
    def __init__(self, code: str, message: str, status: int = 400) -> None:
        # code not snake_case / > 64 chars → ValueError; status not an int in 400–599 (bool rejected)
        # → ValueError; message empty/blank → ValueError [refined: message required]

class ErrorBody(BaseModel):     code: str; message: str          (frozen)
class ErrorEnvelope(BaseModel): error: ErrorBody                 (frozen) → {"error": {"code", "message"}}

def install_error_handlers(app: FastAPI) -> None:
    DomainError            → exc.status, {code, message}
    RequestValidationError → 422 "validation_error", message = "; ".join(f"{'.'.join(loc)}: {msg}")
                             for the first 5 errors (+ "(and N more)"); never `input` or `ctx`
    StarletteHTTPException → 404 "not_found" · 405 "method_not_allowed" (exc.headers kept → Allow)
                             · else f"http_{status}"; message = detail if it's a str, else the HTTP
                             status phrase; a status that allows no body (204/304) → empty response
    Exception              → 500 "internal_error", "Something went wrong on our side. Please try again."
```
- The 500 handler **doesn't log**: Starlette re-raises after sending the response and uvicorn logs the traceback once (`uvicorn.error`), which F1.5 turns into one redacted JSON line, so there's no duplicate. F1.5's real-server test proves it.
- [refined] **OpenAPI:** the `/api` router declares `responses={422: ErrorEnvelope, "default": ErrorEnvelope}`, so FastAPI stops advertising its `HTTPValidationError` shape, which our handler never returns (David V. may generate a client from `/openapi.json`).
- Messages are English developer/Claude text, not UI text (arch 9.1: "the UI shows a generic error"; the app maps `code`), so `app/i18n` isn't involved.

**Contract impact.** 🆕 `from app.errors import DomainError, ErrorEnvelope, ErrorBody, install_error_handlers`. Error codes owned by F1: `validation_error`, `not_found`, `method_not_allowed`, `internal_error`, `http_<status>`. Everyone's routes raise `DomainError`, never an `HTTPException` with a dict detail. Arch 9.1 gets the code list (§5).

**Design.**
```python
REDACTED = "[REDACTED]"
def redact(text: str) -> str: ...     # public: B15 can reuse it for tool_calls input/output
    # sk-ant-[A-Za-z0-9_-]+ · (?i)bearer\s+[A-Za-z0-9._~+/=-]+ (keeps "Bearer ") ·
    # JWT eyJ[\w-]{5,}\.[\w-]{5,}\.[\w-]* (catches the WebSocket `?token=` that uvicorn logs, arch 5.1) ·
    # scheme://user:PASSWORD@ → scheme://user:[REDACTED]@ · IBAN [A-Z]{2}\d{2}(?: ?[A-Z0-9]){11,30}
    # Card-digit runs: not redacted (13-digit epoch-ms false positives), as agreed.

class JsonFormatter(logging.Formatter):
    # payload: ts (record.created → UTC "2026-06-15T09:00:00.123Z"), level, logger, msg,
    # then extras (non-standard LogRecord attributes, minus uvicorn's `color_message`; core keys win),
    # then exc (formatted traceback) / stack. Every value goes through _jsonable(): str → redact;
    # int/float/bool/None kept; dict/list/tuple recursed; anything else (Decimal, date, SecretStr…)
    # → redact(str(value)), "<unprintable>" if str() raises. A bad format call (`"%s %s", 1`) still
    # yields a line (raw msg + args). json.dumps(ensure_ascii=False, default=str).

def configure_logging(level: str) -> None:
    # root: remove only *our* handler(s), add one `_StderrHandler` (looks sys.stderr up at emit time,
    # like logging.lastResort, so pytest's capture swaps don't break it) with JsonFormatter and the level;
    # root level = level. uvicorn, uvicorn.error, uvicorn.access: handlers cleared, propagate=True,
    # except uvicorn.access when uvicorn disabled it (--no-access-log: no handlers + propagate False).
    # Unknown level → ValueError. Idempotent.
```
- [refined] Redaction lives **in the formatter**, not in a `logging.Filter`: a logger-level filter doesn't see records propagated from child loggers, and formatting is the one place where msg, args, extras and the exception text are all strings. Same effect as a handler filter, one choke point.
- `ts` is the real wall time (`record.created`), not `app.clock`: logs must show when things happened, even in SIM_MODE. (Not a clock-rule violation: no `now()` call.)
- `create_app` order: settings → `configure_logging(settings.LOG_LEVEL)` → app → handlers → routers → `logger.info("app_configured", extra={"settings": settings.model_dump(mode="json")})` (secrets show as `**********`; gives the real-server test something to check).
- Output goes to **stderr**, so CLI tools (seed, demo client) keep stdout for their results.

**Contract impact.** 🆕 `from app.logging import configure_logging, redact`. Log line shape (one JSON object per line: `ts`, `level`, `logger`, `msg`, extras, `exc`) is what B15 and the demo runbook read. CLIs (B12 seed, D4 demo client) should call `configure_logging` themselves (HANDOFFS proposal).
