**Probed before planning** (scratch files only, pydantic 2.14.1, mypy 2.4.1). These results drove the design:
- An `Annotated[Decimal, BeforeValidator, PlainSerializer(float, when_used="json"), WithJsonSchema(number)]` money type validates, dumps as a JSON number and has `{"type":"number"}` as its schema. `Field(gt=0)` still applies.
- `model_copy(update=…)` **skips validation**: it accepted `amount = -5`. So `DomainModel.replace()` re-validates instead (R6).
- `MappingProxyType` in a field makes the serializer warn, which `filterwarnings = error` turns into an error. So nested maps are typed `Mapping` (read-only for mypy) and stay dicts at runtime (R7).
- Under an ambient `decimal` context with `prec=3`, `Decimal(500)/3 == 166`. So money maths runs in an explicit context.
- A `time` with seconds dumps to `"12:00"` when the serializer is `%H:%M`, which loses the seconds. So times must be whole minutes.
- `Ratio` floats accept `True` as `1.0` in lax mode. So bools get an explicit reject.
- The `alias="from"` field works for mypy with `validate_by_name`. The pydantic plugin's `init_typed` makes `Model(amount=1)` a mypy error, so builders use `model_validate` (R8).
- A per-type fact value works through a `field_validator("value", mode="before")` that picks the model from `info.data["type"]`.

### Step 2 · money helpers + the `Money` field type (`money.py`)

**Design:**
```python
MoneyLike = Decimal | int | float | str
CENT = Decimal("0.01")
MAX_ABS = Decimal("10000000000")          # NUMERIC(12,2) (arch 4.3): |x| < 10^10
_CTX = Context(prec=28, rounding=ROUND_HALF_UP, traps=[InvalidOperation, DivisionByZero, Overflow])

def to_decimal(value: MoneyLike) -> Decimal      # Decimal(str(value)); rejects bool, NaN, ±inf, non-numbers → ValueError
def to_money(value: MoneyLike) -> Decimal        # to_decimal → quantize(CENT, ROUND_HALF_UP) in _CTX; -0.00 → 0.00; |x| ≥ 10^10 → ValueError
class Split(NamedTuple): own: Decimal; others: Decimal
def split_share(total: MoneyLike, people: int) -> Split   # own = to_money(total / people); others = to_money(total) − own
def share_each(others: MoneyLike, count: int) -> Decimal  # to_money(others / count): display only (the total stays exact)
def decimal_to_json(value: Decimal) -> float
Money = Annotated[Decimal, BeforeValidator(to_money),
                  PlainSerializer(decimal_to_json, return_type=float, when_used="json"),
                  WithJsonSchema({"type": "number"})]
```
- **Key decisions.**
  - The float goes through `str()`: `Decimal(1.005)` is 1.00499…, while `Decimal("1.005")` rounds to 1.01.
  - The rounding is half-up (away from zero on ties: −2.675 → −2.68).
  - Every operation runs in the private context `_CTX`, so the caller's thread- or task-local decimal context can't change a result.
  - `others = total − own`, so the two shares always add up exactly.
  - `people` must be an `int ≥ 1` and not a `bool`. `total` and `others` must be ≥ 0. A total of 0 is allowed and gives (0, 0).
  - `split_share` rounds `total` first (a no-op for the 2-dp amounts that come from the DB).
- **Money in JSON (how it's documented).** `Money` stays a `Decimal` in Python (`model_dump()`). In JSON mode (`model_dump(mode="json")`, `model_dump_json()`, FastAPI responses) it's a **JSON number** equal to the 2-dp value. JSON numbers drop trailing zeros, so 31.20 is written `31.2` (Q7). This is exact: every money value has at most 12 significant digits (under 10^10 with 2 dp), and a float's shortest repr round-trips 15. The JSON schema is `{"type":"number"}` (OpenAPI for David V., tool schemas for A2). Validating from JSON goes `float → str → Decimal`, so a round trip gives the same `Decimal`. This explanation goes in the `money.py` docstring and the step report, and a one-line clarification of arch 9.1 is proposed (§5).
- **What `to_money` accepts.** Machine format only. `"10.000"` (Romanian for ten thousand) would parse as 10.00. User-formatted text must never reach it; the docstring says so, and the language test pins it.

**Contract impact.** 🆕 `to_money`, `split_share` (now a `Split` named tuple, still equal to the `(own, others)` tuple), `share_each`, `to_decimal`, `Money`. danutu (every engine amount) and A3 (`annotate_transaction`) import them. The "money dumps as a JSON number" test moves here from F2 step 3, because the models use `Money` from step 3 on (R2).

### Step 3 · model base + transactions (`models.py`, part 1)

**Design:**
```python
class DomainModel(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", validate_by_name=True,
                              validate_by_alias=True, serialize_by_alias=True)
    def replace(self, **changes: object) -> Self:      # re-validates (model_copy(update=) doesn't)
        return self.model_validate({**self.model_dump(by_alias=False), **changes})

Id = Annotated[int, Field(gt=0)]
NonEmptyStr = Annotated[str, StringConstraints(strip_whitespace=True, min_length=1)]
Mcc = Annotated[str, Field(pattern=r"^\d{4}$")]          # MCCs like 0742 have a leading zero
PositiveMoney = Annotated[Money, Field(gt=0)];  NonNegMoney = Annotated[Money, Field(ge=0)]
Ratio = Annotated[float, BeforeValidator(_no_bool), Field(ge=0, le=1, allow_inf_nan=False)]
NonNegFloat = Annotated[float, BeforeValidator(_no_bool), Field(ge=0, allow_inf_nan=False)]
Factor = Annotated[Decimal, BeforeValidator(to_decimal), PlainSerializer(decimal_to_json, ...)]   # multiplies money

class Item(DomainModel):   name: NonEmptyStr; qty: int = Field(1, ge=1); amount: NonNegMoney | None = None
class TxView(DomainModel):
    id: Id; occurred_at: AwareDatetime; merchant_raw: str (1–200); merchant: str | None; merchant_id: Id | None
    mcc: Mcc | None; category: Category | None   # None only before the first evaluation (R10)
    direction: Direction; amount: PositiveMoney; effective_amount: NonNegMoney
    items: tuple[Item, ...] | None = None        # None = no item data (D32), () = an empty receipt
    description: str | None; purpose / beneficiary / annotation_source / decision: … | None
    annotation_confidence / life_fit / anomaly_score / unexplained: Ratio | None
    explanation: str | None; matched_fact_id / matched_rule_id / pot_id / receivable_id: Id | None
    # rule: effective_amount ≤ amount
class Merchant(DomainModel): id: Id; canonical_name: NonEmptyStr; aliases: tuple[str, ...]; category: Category
                             mcc: Mcc | None; typical_basket: PositiveMoney | None; multi_category: bool = False
```
- **Scores are `float`** (`Ratio`, 0–1, finite) and **money or anything multiplied with money is `Decimal`** (`Money`, `Factor`). This is Q1. Python raises `TypeError` on `Decimal * float`, so the split has to be clean.
- Sequences are tuples (deeply immutable). There's no `user_id` on any view: isolation is the services' job, and `UserContext` carries the one `user_id`.
- `TxView` is the arch §15 `Transaction` (doc fix proposed in §5).
