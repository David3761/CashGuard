### Step 2: the real `LLM`: request building and the call (~60 lines)

> **Changed after the A1.2 review (2026-10-29), see the report's "Review of A1.2":**
> - the call is streamed internally (`client.beta.messages.stream(**params)` → `get_final_message()` → a plain `BetaMessage`), so the 30 s read timeout bounds the silence between chunks and a broken stream isn't re-generated;
> - `max_tokens` follows the effort (`MAX_TOKENS_BY_EFFORT`: 8 000 / 16 000 / 32 000 / 64 000 / 64 000); `low` keeps the approved 8 000;
> - `base_url` is explicit; `ANTHROPIC_CUSTOM_HEADERS` disables the client (fail closed); `ANTHROPIC_LOG` is capped;
> - a caller's `cache_control` in messages or tools is rejected;
> - the `LLM` owns the injected `http_client`.

**Files.** `app/agent/llm.py`, `tests/unit/test_llm.py`.

**Design.**
```python
MAX_TOKENS: Final = 8000
TIMEOUT_S: Final = 30.0
MAX_RETRIES: Final = 2
REFUSAL_FALLBACK_BETA: Final = "server-side-fallback-2026-07-01"

def build_params(system: Sequence[str], messages: Sequence[BetaMessageParam],
                 tools: Sequence[BetaToolParam], *, model: str, effort: Effort,
                 refusal_fallback: bool) -> MessageCreateParamsNonStreaming:   # pure (SDK TypedDict)
    params = {
        "model": model, "max_tokens": MAX_TOKENS, "output_config": {"effort": effort},
        "system": [{"type": "text", "text": p, "cache_control": {"type": "ephemeral"}}
                   for p in check_system(system)],        # one breakpoint per part (arch 6.8)
        "messages": list(messages),                       # passed through unchanged
        "cache_control": {"type": "ephemeral"},           # automatic breakpoint on the tail (Q2)
    }
    if tools:            params["tools"] = list(tools)    # order kept (deterministic → cacheable)
    if refusal_fallback: params["betas"] = [REFUSAL_FALLBACK_BETA]; params["fallbacks"] = "default"
    return params        # never: temperature, top_p, top_k, tool_choice, thinking, stop_sequences

class LLM:   # satisfies LLMClient
    def __init__(self, *, api_key: str | None, model: str, effort: Effort, refusal_fallback: bool,
                 max_retries: int = MAX_RETRIES, http_client: httpx2.AsyncClient | None = None) -> None:
        # api_key None → no SDK client at all (never the SDK's env/profile credential chain)
        self._client = None if not api_key else AsyncAnthropic(
            api_key=api_key, timeout=TIMEOUT_S, max_retries=max_retries, http_client=http_client)
    async def create(self, system, messages, tools=()) -> BetaMessage:
        params = build_params(...)               # programming errors surface first (ValueError/TypeError)
        if self._client is None:
            raise LLMUnavailable("ANTHROPIC_API_KEY is not set")
        return await self._client.beta.messages.create(**params)   # always the beta endpoint (D1)
    async def aclose(self) -> None: ...          # B9 calls it on shutdown; tests close every client
```
`max_retries` and `http_client` are constructor parameters so tests can inject `httpx2.MockTransport` and skip backoff sleeps; production uses the defaults.

### Step 3: error mapping + logging (~45 lines)

> **Updated after the A1.2 review (2026-10-29).** Step 2 now **streams** internally (review R1), which moves where failures surface. Step 3 must map all three:
> 1. **before the stream opens:** an `APIStatusError` with the real HTTP status (the SDK has already retried 408/409/429/5xx);
> 2. **an `error` event mid-stream:** an `APIStatusError` whose status is **200**, so it's classified by its error **type** (`overloaded_error`, `api_error`, `rate_limit_error` → unavailable; to be verified against the SDK during the step);
> 3. **a transport failure mid-stream:** a raw `httpx2` exception (`ReadTimeout`, `RemoteProtocolError`…), seen in step 2's broken-stream test → `LLMUnavailable`, not retried.
>
> Also in step 3: **R5**, one WARNING when Claude declines (`stop_reason` `refusal`), with the category, the model that answered and whether the fallback was on, never the content; and **R6**, replace the local `Effort` with `from app.config import Effort` (needs the rebase onto `dga-final`).

**Files.** `app/agent/llm.py`, `tests/unit/test_llm.py`.

**Design.**
```python
_TRANSIENT_4XX: Final = frozenset({408, 409, 429})   # the SDK retries these too
log = logging.getLogger(__name__)                       # F1.5 formats it as JSON; no import of app.logging needed

def classify_status(status: int) -> type[LLMUnavailable] | type[LLMBadRequest]:   # pure
    return LLMUnavailable if status in _TRANSIENT_4XX or status >= 500 else LLMBadRequest

# in create(), most specific first (skill: never string-match):
except anthropic.APIStatusError as err:      # 4xx/5xx after the SDK's retries
    → LLMUnavailable (warning log) or LLMBadRequest(status_code, error_type=err.type,
      request_id=err.request_id) (error log), `raise … from err`
except anthropic.APIConnectionError as err:  # incl. APITimeoutError
    → LLMUnavailable("Claude API unreachable (connection error or timeout)")
except anthropic.AnthropicError as err:      # anything else the SDK raises
    → LLMUnavailable
# never caught: asyncio.CancelledError (BaseException) → A7's timeout keeps working
# on success: log.info("llm call", extra={...}) with response model (shows a fallback model),
# stop_reason, refusal category, input/output/cache_read/cache_write tokens. Never content, never the key.
```

**Contract impact.** `LLMUnavailable` / `LLMBadRequest` semantics fixed (arch §11 rows "Anthropic API error / timeout"); A6/A7 catch `LLMError` for the fallback and may log the subtype. `classify_status` exported for the mapping table.

### Step 4: `FakeLLM` API-conformance checks (recommended, Q3) (~60 lines test support)

**Why.** A permissive fake lets A6 pass tests that the real API would reject with a 400. The two classic agent-loop bugs are tool results split or misordered, and history/tool edits that invalidate replayed thinking blocks (the D21 risk, §5 #4). The fake should fail exactly where the API would.

**Files.** `tests/fakes/fake_llm.py`, `tests/unit/test_fake_llm.py`.

**Design.** `FakeLLM(script, *, strict: bool = True)`. In strict mode every `create()` checks the request; a violation raises `FakeLLMProtocolError(FakeLLMFailure)` (a `BaseException`, like `ScriptExhausted` since the A1.1 review, so an `except Exception` can't swallow it) and is kept in `fake.violations`, so `assert_consumed()` fails even if something swallowed it. Since D46, check 4 also flags **any change of the tool set between requests of one run**, with or without thinking blocks. Not checked (review A1.1 #3, rejected): a scripted `tool_use` naming a tool the request didn't offer, because Sonnet 5.5 can return such names and A3/A7 must test that defence; tests assert `requests[i].tool_names` instead. Checks, each mirroring a real API 400 (the exact rules are re-checked against the live tool-use docs during the step, and the happy path by step 5's live round trip):
1. `messages` non-empty, the first message is `user`; the last is not `assistant` (prefill → 400 on Sonnet 5.5).
2. Every assistant message with `tool_use` blocks is **immediately** followed by a `user` message whose content **starts** with exactly one `tool_result` per `tool_use` id (no missing, extra or duplicate ids); text may follow the results.
3. A `tool_result` must answer a `tool_use` of the immediately preceding assistant message.
4. **Preserved thinking:** when a request replays an assistant turn equal to a response this fake produced, and that response holds `thinking`/`redacted_thinking` blocks, the request's system parts, its tool set (compared name-sorted: reordering is allowed) and every message before that turn must equal the producing request's.

**Contract impact.** A6's tests get these checks for free (`strict=True` default); `strict=False` exists for tests that deliberately send malformed history.

**Test analysis.**

| # | Category | Case | Expected | Why it matters |
|---|---|---|---|---|
| 1 | happy | user → assistant [thinking, tool_use ×2] → user [tool_result ×2] → end_turn, tools/system unchanged | no violation | the normal A6 round trip, incl. parallel calls |
| 2 | boundary | a text block **after** the tool_results in the same user message; `is_error: true` results; a mid-conversation `role: "system"` message after a user turn | allowed | legal shapes must not be flagged |
| 3 | invalid | a tool_use with no tool_result next | violation naming the missing id | API: "tool_use ids were found without tool_result blocks immediately after" |
| 4 | invalid | 2 results split over 2 user messages | violation | arch 6.8: all results in **one** message |
| 5 | invalid | a tool_result id not in the previous assistant turn; a duplicate id | violation | API rejects unknown / duplicate ids |
| 6 | invalid | text **before** the tool_results | violation | results must come first |
| 7 | invalid | first message `assistant`; last message `assistant`; empty `messages` | violation | prefill is a 400 on Sonnet 5.5 |
| 8 | errors | a violation raised inside a caller that catches `Exception` | `assert_consumed()` still fails | A6's broad except can't hide a protocol bug |
| 9 | security | — | — | see N/A |
| 10 | invariants (preserved thinking) | after a response with thinking: next request with a **different tool set** (`set_goal` → `update_goal`, D21); with a rebuilt system part; with an edited earlier message | violation "400 on accounts created on or after 2026-08-31 (preserved thinking)" | catches the arch 6.3/D21 conflict in A6's tests before it hits the demo |
| 11 | invariants (preserved thinking) | same tools in a different order; a response **without** thinking blocks followed by a changed tool set | allowed | name-sorted binding; the rule only applies when blocks are replayed |
| 12 | regression | `strict=False` | none of the checks run | escape hatch stays working |

**Not applicable:** security (no secrets/ids), concurrency (checks are per request, pure), idempotency (checks don't mutate), time, money, language, personalisation, performance.

**Red run.** `strict` accepted but no checks implemented. Expected: every invalid case fails with `DID NOT RAISE FakeLLMProtocolError`; the allowed cases already pass (they are guards; each is mutation-tested afterwards by temporarily breaking one check, as F1.1 did).

## 5. Proposed shared-doc changes (the boss edits; A1 never does)

1. **Arch 6.8 "Refusal fallback" row (correction):** SDK 2.3.0 exposes `betas`/`fallbacks` only on `client.beta.messages.create`, so the wrapper always calls the beta endpoint and returns `BetaMessage` (with an extra `fallback` block type). On Sonnet 5.5, `"default"` only rescues `cyber` and `frontier_llm` declines (served by Sonnet 5), not `general_harms`/`bio`/`reasoning_extraction`; Claude API only; the fallback runs without Sonnet 5.5's thinking blocks; ~1 h sticky routing. Switch: `ANTHROPIC_REFUSAL_FALLBACK` (Q1).
2. **Arch 6.8 "Prompt caching" row (addition, Q2):** a breakpoint on every system part (≤ 3: frozen rules, trigger instructions, snapshot) + top-level automatic `cache_control` for the growing conversation tail (the skill's recommended combination for agent loops; 4 breakpoints max). Minimum cacheable prefix on Sonnet 5.5: 512 tokens.
3. **Arch 6.8 "Intermediate text" row (precision):** short remarks between tool calls can still arrive as `text` blocks in a `tool_use` response; only the final `end_turn` response's text is the reply (6.3 already reads only that).
4. **⚠ Arch 6.3 + D21 (for A6/A2, decide before A6):** rebuilding `tools` between iterations of one run edits the conversation prefix, which invalidates replayed thinking blocks → **400 on accounts created on or after 2026-08-31** (Sonnet 5.5 preserved thinking), and restarts the prompt cache. Proposal: compute `tools_for` **once per run** (A3's executor already answers `set_goal` with an active goal by `goal_already_active`), or send `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` (beta `thinking-binding-controls-2026-08-01`). The snapshot must also stay fixed within a run (6.3 already builds it once).
5. **Arch 6.3 stop reasons (for A6):** whitelist instead of blacklist: `end_turn` → reply, `tool_use` → loop, **anything else** (`refusal`, `max_tokens`, `pause_turn`, `stop_sequence`, `model_context_window_exceeded`, `compaction`) → fallback. Today's pseudocode treats unknown reasons as `end_turn`.
6. **Arch §3 + `.env.example`:** add `ANTHROPIC_REFUSAL_FALLBACK` (§3 above).
7. **Arch §11 / work-breakdown A1:** the mapping: 408, 409, 429, ≥ 500, connection errors, timeouts, a missing key → `LLMUnavailable`; any other 4xx → `LLMBadRequest`. SDK 2.3.0 facts: API version `2026-10-21` (sampling params are 400s on every model), the key goes as `Authorization: Bearer`.
8. **Work-breakdown §0.1 / how-we-work §7:** respx can't mock the Anthropic SDK (it uses `httpx2`); wrapper tests use `httpx2.MockTransport` via `http_client=`.
9. **Latency note for A6 / B9:** 30 s × (1 + 2 retries) + backoff ≈ 92 s worst case, and the SDK obeys `retry-after` without a cap (a 429 can wait 60 s). Chat needs its own overall deadline, like A7's 5 s template.
10. **F1.5:** cap the `anthropic`, `httpx2`, `httpx`, `httpcore` loggers at WARNING: at DEBUG the SDK logs the full request body (snapshot + user messages = financial data).
