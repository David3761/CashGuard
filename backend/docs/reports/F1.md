### F1.2: Settings + `.env.example`

> Plan: [`docs/plans/F1.md`](../plans/F1.md) §F1.2, approved by David G. on 2026-10-29 with Q1 = fallback **off**, Q3 = conftest fixtures **yes**, Q4 = keep `KEYCLOAK_CRON_CLIENT_SECRET`.

**What & why.** Every environment variable the app reads, typed and validated in one frozen `Settings` model, so a bad value stops the app at startup instead of breaking the demo later. A1 is blocked on it. `create_app(settings)` now stores the settings on the app; routes read them through a typed dependency. Tests are hermetic: they never read the developer's real `.env` or shell variables, where a real key would mean real, paid Claude calls.

**Contract impact.**
- 🆕 `app.config`: `Settings`, `get_settings()` (cached), `get_app_settings(request)` (FastAPI dependency), `BACKEND_DIR`, `ENV_FILE`. **Also found while fixing.**
- **The fallback hid bugs (twice).** Under R5 and R6 my computation came out empty, and the code fell back to Starlette's own header. That header was correct only because each test path had a single route, so the tests passed by luck and mutations V5 / V6 survived. The tests now use **two routes on one path** (a mount, an included router), where only the computation gives the right answer. Both mutations are caught.
- **E4 survived the re-run:** with the in-router `DomainError` handler removed, the new outer middleware answered everything. But the in-router handler is needed. Without it, a route's `DomainError` skips the user middleware on the way out, so a CORS-style middleware couldn't decorate error responses, and `call_next` would raise. New test: a stamping `BaseHTTPMiddleware` must see the error response. E4 is caught now.
- **V7c (late raise) first survived:** httpx's transport silently ignores a second response start. The test now calls the app as raw ASGI and checks every message sent.
- **Not mutation-provable:** the "add the middleware once" guard in `install_error_handlers`. A second identical layer behaves the same; the guard only avoids a redundant layer.
- **One expectation of mine was wrong, not the code:** in the hand-made-errors test I expected `body.x`. The route declares no body, so `x` *is* undeclared and `<…>` is exactly R2's rule. I corrected the expectation, not the code.
- **Message format change:** validation messages are now `field.path: fixed text` (e.g. `body.amount: field required`, `query.a: must be an integer`). The earlier pydantic phrasings are gone.
- **Size:** `app/errors.py` is now 206 statements, well past the ~150-line step guideline, because the review asked for sanitised paths, WebSocket handling and middleware handling. If you prefer, the validation-message part (`_TEXTS`, `_step`, `_error_path`, ~80 lines) can move to its own module in a follow-up.

### F1.5: JSON logging (fast mode: happy-path tests only, no mutation runs or independent review, per David G.)

- **Built:** `app/logging.py`.
  - `configure_logging(level)`: idempotent, replaces only its own handler; one JSON object per line on stderr with `ts` (UTC `Z`), `level`, `logger`, `msg`, extras and `exc`; `ensure_ascii=False`.
