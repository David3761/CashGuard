### F2.1a: the first enums + the fixed category sets

**What & why.** This step adds the value lists C1 is blocked on (`Category`, `Purpose`, `Beneficiary` for its labels and `merchants.json`) and the ones bomboe's B2 needs first for its CHECK constraints. Each list is a `@unique` `StrEnum` whose values are exactly the arch doc's, in the doc's order. Two fixed sets from arch 4.5 come with it: the household-scaled categories (for E6) and the never-asked categories (for C6/C7).

**Contract impact.** 🆕 The enum values are now the contract:
- B2 generates its `CHECK (col IN …)` constraints from these enums.
- C1 labels every `Category` / `Purpose` / `Beneficiary`.
- A2 builds its tool-schema `enum`s from them.

From here on, renaming or removing a value is a contract change. Member names are `value.upper()` (`Beneficiary.SELF`, `Decision.ASK_LATER`). No arch doc change is needed: every value is copied from the doc.

### F2.2: money helpers + the `Money` field type (`app/domain/money.py`)

**What & why.** This step adds the money rules every engine and context function uses (work-breakdown 0.3 rule 2): `to_money` (Decimal, half-up to the cent, read via `str()`), `split_share` (own + others always add up exactly), `share_each` (display only), `to_decimal` (exact, for multipliers) and the `Money` pydantic field type, which dumps as a JSON **number** (arch 9.1). danutu (every engine amount), C1.4 and A3 (`annotate_transaction`) are waiting for it. **Contract impact.** 🆕 `app.domain.money`:
- `to_money(value) -> Decimal`
- `to_decimal(value) -> Decimal`
- `split_share(total, people) -> Split(own, others)`: a `NamedTuple`, so it still equals the `(own, others)` tuple of the spec

Errors:
- a bad value is a `ValueError` (so a `Money` field gives a pydantic `ValidationError`);

- every message names the argument and the value.

**How money is serialised (as the plan asked to document).** `Money = Annotated[Decimal, BeforeValidator(to_money), PlainSerializer(float, when_used="json"), WithJsonSchema({"type": "number"})]`:
- `model_dump()` gives a `Decimal`;
- `model_dump(mode="json")`, `model_dump_json()` and FastAPI responses give a JSON number;
- the OpenAPI / tool schema says `"type": "number"`.

The conversion is exact: every storable amount has ≤ 12 significant digits, a float's shortest repr keeps 15, and reading the JSON back goes `float → str → Decimal`. This is proven by a property test over the whole storable range. It's written in the module docstring.
