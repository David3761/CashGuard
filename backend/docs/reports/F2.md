### F2.1a: the first enums + the fixed category sets

**What & why.** This step adds the value lists C1 is blocked on (`Category`, `Purpose`, `Beneficiary` for its labels and `merchants.json`) and the ones bomboe's B2 needs first for its CHECK constraints. Each list is a `@unique` `StrEnum` whose values are exactly the arch doc's, in the doc's order. Two fixed sets from arch 4.5 come with it: the household-scaled categories (for E6) and the never-asked categories (for C6/C7).

**Contract impact.** 🆕 The enum values are now the contract:
- B2 generates its `CHECK (col IN …)` constraints from these enums.
- C1 labels every `Category` / `Purpose` / `Beneficiary`.
- A2 builds its tool-schema `enum`s from them.

From here on, renaming or removing a value is a contract change. Member names are `value.upper()` (`Beneficiary.SELF`, `Decision.ASK_LATER`). No arch doc change is needed: every value is copied from the doc.

**Implementation.** `app/domain/enums.py` has one `@unique class X(StrEnum)` per list, explicit `NAME = "value"` members, and a one-line docstring with the arch section. The two sets are `Final[frozenset[Category]]`, each with a docstring. Values are written out, not `auto()`, so the file can be read line by line against the doc.

**Self-review findings.**
- `ruff format` rewrote the golden lists to one value per line (magic trailing comma). I kept that: it's easier to diff against the doc.
- `ruff` SIM300 flagged `HOUSEHOLD_SCALED_CATEGORIES == {…}` as a "Yoda condition" (it treats UPPER_CASE names as constants). Changed to `set(X) == {…}`, which also says what is compared.
- The fixed-set test ids were `fixed_set0/1`. They're now named.
- **An independent cross-check against the doc text.** A throwaway script parsed the arch doc itself: the 4.5 lines, the 4.5 Purpose table, and the `transactions` / `products` / `users.language` / `coach_style` rows. It compared them with the enums without using the hand-copied golden lists. All 10 enums and the household set came out **OK**. (The script's first version mis-parsed the doc's `` `a / b / c` `` code spans. The fix was in the script; the enums didn't change.)
- How-we-work §5 checklist: values match the doc; nothing labels a purchase good or bad (`Purpose` replaces good/bad); no user-facing text (labels are C1's); no clock, money or IO; strict types; `__init__.py` files are empty.
