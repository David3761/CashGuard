### A1.1: error types, the `LLMClient` protocol and `FakeLLM`

**What & why.** The pieces every later agent task builds its tests on, with no Settings and no network. `app/agent/llm.py` gets the error types the agent falls back on (arch §11), the `LLMClient` protocol A6/A7/A10 will type against, and `check_system` (the system-prompt guard shared by the real client and the fake). `tests/fakes/fake_llm.py` is `FakeLLM(script)`: it serves scripted responses in order, records a deep-copied snapshot of every request, raises `ScriptExhausted` when the script runs out, and has `assert_consumed()` for the end of a test. The builders return **real, validated SDK objects** (`BetaMessage`), so a test can't script a shape the API never sends.

**Contract impact.** 🆕 (no existing contract changed)
- `app.agent.llm`: `Effort`, `MAX_SYSTEM_PARTS = 3`, `LLMError` ⊃ `LLMUnavailable`, `LLMBadRequest(message, *, status_code, error_type, request_id)`, `LLMClient.create(system: Sequence[str], messages: Sequence[BetaMessageParam], tools: Sequence[BetaToolParam] = ()) -> BetaMessage`, `check_system(system) -> tuple[str, ...]` (1–3 non-blank parts; a bare `str` is a `TypeError`).
- `tests.fakes.fake_llm`: `FakeLLM`, `RecordedRequest(system, messages, tools)` + `.tool_names`, `ScriptExhausted` (an `AssertionError`, **not** an `LLMError`), builders `text`, `tool_use(name, args, *, tool_use_id)`, `thinking`, `redacted_thinking`, `message(*blocks, stop_reason=…, input_tokens, output_tokens, cache_read, cache_write, model, msg_id, refusal_category)`, `end_turn`, `tool_round`, `refusal`, `cut_off`.
- Who uses it: A6, A7, A9, A10 tests; the response type everyone handles is `anthropic.types.beta.BetaMessage` (plan D1).

### A1.2: the real `LLM`: request building and the call

**What & why.** The real client, without error mapping yet (that's step 3). `build_params()` is a pure function that builds the arch 6.8 request. `LLM` holds one `AsyncAnthropic` (timeout 30 s, `max_retries=2`) and always calls `client.beta.messages.create(**params)`, so the result is a `BetaMessage` whether the refusal fallback is on or not (plan D1). Without a key, no SDK client is built at all: `create` raises `LLMUnavailable` and sends nothing, instead of the SDK silently looking for credentials in env vars or an `ant auth login` profile.

**Contract impact.** 🆕 in `app.agent.llm`:
- `MAX_TOKENS = 8000`, `TIMEOUT_S = 30.0`, `MAX_RETRIES = 2`, `REFUSAL_FALLBACK_BETA = "server-side-fallback-2026-07-01"`.
- `build_params(system, messages, tools, *, model, effort, refusal_fallback) -> MessageCreateParamsNonStreaming`.
- `LLM(*, api_key, model, effort, refusal_fallback, max_retries=2, http_client=None)` with `create()` and `aclose()`.

The request it sends (exact, checked on the wire): `model`; `max_tokens: 8000`; `output_config: {"effort": …}`; `system` with one text block per part, each `cache_control: ephemeral`; top-level `cache_control: ephemeral` (the automatic tail breakpoint, D48); `messages` and `tools` unchanged and in order (no `tools` key when empty); with the fallback on (D45: off by default), header `anthropic-beta: server-side-fallback-2026-07-01` + `fallbacks: "default"`. Never sent: `temperature`, `top_p`, `top_k`, `tool_choice`, `thinking`, `stop_sequences`. The SDK sends the key as `authorization: Bearer …` and `anthropic-version: 2026-10-21`.

For later users: A6/A7/A10 handle `BetaMessage`; A4/A5/A6 pass `system` as ≤ 3 non-blank parts (rules, optional trigger instructions, snapshot); B9 builds one `LLM` and calls `aclose()` on shutdown (step 5 adds `from_settings` / `get_llm`).

### A1.3: error mapping + logging (incl. mid-stream failures, R5, R6)

**What & why.** `create()` now never lets an SDK or HTTP-layer error escape. Every failure becomes one of the two types the agent falls back on (arch §11):
- **`LLMUnavailable`:** transient, or no usable configuration;
- **`LLMBadRequest`:** Claude rejected our request, a bug or config error, logged at ERROR with the API's own message.

Since step 2 streams, failures surface in **three places**, and each was probed against the SDK before writing the tests:

| Where | What the SDK raises | Becomes |
|---|---|---|
| before the stream opens | `APIStatusError` with the real status (already retried by the SDK for 408/409/429/5xx), or `APIConnectionError` / `APITimeoutError` | by status, or unavailable |
| an `error` event inside the stream | `APIStatusError` with status **200** and `.type` | by error type: only a request-error type is a bad request |
| a broken stream | a raw `httpx2` error (`ReadTimeout`…); a stream with no `message_stop` is **returned** as a partial message (`stop_reason None`); bad tool JSON (`ValueError`); events out of order (`RuntimeError`); no message at all (a bare `assert`) | unavailable, never a half message |

Logs (logger `app.agent.llm`; stdlib logging, since the repo has no `app/logging.py` yet):
- every successful call: one INFO line (model, stop reason, input/output tokens, `cache_read`, `cache_write`; arch 6.8 "check the cache hits");
- **R5:** one WARNING when Claude declines (category, the model that answered, fallback on/off);
- WARNING for unavailable, ERROR for bad requests.

Never logged: the key, the content of the user's messages, Claude's reply. **R6:** `Effort` now comes from `app.config` (one definition).

**Contract impact.**
- `create()` raises only `LLMUnavailable`, `LLMBadRequest`, the `ValueError`/`TypeError` of an invalid prompt (a programming error, before anything is sent) or `CancelledError` (unchanged, so `asyncio.timeout` works for A6/A7/B9).
- A refusal is **returned** (with its WARNING); A6 answers it with the template.
- 🆕 `classify(status, error_type) -> type[LLMUnavailable] | type[LLMBadRequest]` (pure).
- `Effort` is imported from `app.config`, not from `app.agent.llm`.
- The step 2 broken-stream test now expects `LLMUnavailable`, with the `httpx2.ReadTimeout` as its cause; still exactly 1 request.

### A1.4: `FakeLLM` API-conformance checks (strict by default)

**What & why.** A permissive fake lets A6 pass tests that the real API would answer with a 400. So `FakeLLM(script, *, strict=True)` now checks every request before serving anything:
- **the docs' tool-use rules,** re-read today on "Handle tool calls": "Tool result blocks must immediately follow their corresponding tool use blocks in the message history. You cannot include any messages between…" and "the `tool_result` blocks must come FIRST in the content array. Any text must come AFTER all tool results." Every tool call is answered exactly once in the next user message; no result answers nothing.
- **prefill:** the last message can't be the assistant's (a 400 on Sonnet 5.5); the first must be the user's.
- **D46:** within a run, the tool list and the system prompt stay exactly as they were. A run = each request that only appends to the previous request + its response, recognised whether A6 echoes the SDK blocks or their dict form.
- **preserved thinking:** once a served response with `thinking`/`redacted_thinking` is replayed, the history before it, the system prompt and the tool set (name-sorted, as the API binds it) must be those of the request that produced it, even in a retry that isn't a continuation.

**Not checked, on purpose** (review A1.1 #3): a scripted call to a tool the request didn't offer. The real Sonnet 5.5 can return one, and A3/A7 must script it to test the executor's defence. M42 shows that check would also break step 1's own tests.

A refusal raises `FakeLLMProtocolError` (a `FakeLLMFailure`, so a `BaseException`: no `except Exception` can swallow it). The request is still recorded, nothing is served, and `assert_consumed()` fails on any violation, even a swallowed one. `strict=False` turns the checks off.

**Contract impact.** 🆕 in `tests.fakes.fake_llm`: `FakeLLMProtocolError`, `FakeLLM(…, strict=True)`, `fake.violations`; `assert_consumed()` also fails on violations. For A6: a test only passes if its conversation is one the real API accepts **and** its tools are computed once per run (D46). A7/A3 can still script undeclared tool calls.
